# Output and verification

## 1. Audit output

Report in priority order:

1. Blockers: unclear purpose or primary task, misleading evidence or data, broken actions, unusable mobile interactions, and similar failures.
2. High-priority issues: repeated content, excessive reading, unclear task or conversion paths, missing states, and related problems.
3. **Evidence or data gaps**: claims lacking proof, interfaces lacking real or labeled sample data, recommended materials, and verification methods.
4. Visual and motion recommendations.
5. Strengths worth retaining.
6. Actual verification performed and any unverified scope.

Point to specific regions or files and explain each recommendation. Do not assign a mechanical score or trigger a rewrite based on the number of findings.

## 2. Build or improvement output

Include only what the task needs:

1. Interface type, audience, use case, and primary user task or conversion action.
2. Core message, interface copy, and primary action.
3. Structure and each region's distinct job.
4. Evidence, real data, interface states, and gaps.
5. Content layering and mobile strategy.
6. Reasons for motion and decorative media choices.
7. SEO, interaction, performance, and delivery requirements when applicable.
8. Actual verification results.

Do not produce a strategy document merely to make the format look complete.

## 3. Self-review checklist

This checklist is for the agent before delivery. It is not a user-facing scorecard and must not mechanically trigger a rewrite.

### Information, evidence, and state

- Can users quickly understand the interface, audience, and use case?
- Is the primary user task or marketing CTA clear?
- Does every important claim have nearby supporting evidence?
- Does product UI expose current state, real or labeled sample data, and recovery paths?
- Have evidence, data, and state gaps been listed separately?
- Are numbers, cases, third-party validation, demos, and real outcomes clearly distinguished?
- Are any regions repetitive, vague, or lacking a distinct job?

### Visuals and content

- Are typography, sizing, spacing, radii, and colors consistent?
- Does every region use the same card or stat template?
- Does decoration or motion compete with the main task or message?
- Are emoji, text-character icons, unnecessary controls, repeated helper copy, or repeated demo disclaimers still present?
- Do headings and body copy wrap naturally and scan easily?

### Mobile and interaction

- Is mobile merely a vertical stack of desktop content?
- Are there overlaps, overflow, broken wrapping, or excessive reading?
- Do tabs, swipers, tables, and horizontal labels support manual operation and useful detail access?
- Are controls and corresponding content visible together when practical?
- Are keyboard behavior, focus, semantic headings, landmarks, and reduced-motion preferences supported?

### Performance and delivery

- Are the primary content, action, state, and critical media available first?
- Do third-party scripts, fonts, or large animation dependencies block the initial interface?
- Do forms, navigation, dialogs, tabs, carousels, and primary actions work in real interactions?
- Are images, social metadata, legal links, and SEO complete for public pages?
- Have relevant build, type, and quality checks been run?
- Have real desktop and mobile interfaces been checked rather than only the code?

A successful build proves engineering behavior, not better copy or design. Finally, verify the user's real task or conversion path.
