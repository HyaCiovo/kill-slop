# 视觉、动效与素材

## 1. 视觉系统

优先使用项目已有 token、字体和品牌规范，不用本 skill 覆盖成熟设计系统。没有设计系统时，再定义字体、字号、行高、间距、圆角、边框和色板。

默认要求：

- 字体不超过两种，字重和层级明确。
- 标题避免孤词，正文自然换行，不硬塞固定行数。
- 低对比度灰字仍须可读，正文满足 WCAG AA。
- 卡片嵌套默认不超过两层。
- 圆角、间距、行高和页边距来自统一 token。
- 主色克制，渐变、发光和玻璃效果必须有明确作用。
- 不让所有区块重复“大标题、灰副标题、三卡片”。
- 不用抽象球体、假 3D、默认图标圆底或抽象 UI mockup 填补空白。
- 不把无信息量的装饰符号塞进文案。

视觉风格没有单一答案。可以编辑式、工业化、playful 或极简，但必须与受众、证据和品牌一致。

## 2. 组件与效果实现

先复用项目已有组件和依赖，确认当前框架、版本、包管理器及现有交互体系。简单样式和过渡可以用 CSS 或现有库完成时，不新增依赖。

需要新增能力时，按需求选择：

- **基础组件**：需要引入 shadcn/ui 时，优先采用其 Base UI 版本，并保持项目现有 token、键盘操作和焦点态，不原样照搬默认皮肤。
- **酷炫组件效果**：用户需要粒子、文字拆分、特殊悬停等 ReactBits 类效果，且确能强化 Hero、关键 CTA 或品牌记忆点时，可以安装 ReactBits。非 React 项目选择与当前框架匹配的 Bits 版本或等价实现，不硬套 React 代码。
- **组件手势与状态动效**：React 项目可考虑 Motion，用于手势、布局变化和局部过渡。
- **视差与复杂场景**：确有视差滚动、滚动时间轴或复杂编排需求时，可考虑 GSAP；React 项目也可根据现有栈选择 Motion。不要为简单淡入或位移安装大型动画库。

安装前说明新增依赖解决了什么现有方案无法合理实现的问题。使用后检查包体、移动端性能、触摸行为和 `prefers-reduced-motion`，不因组件演示效果好就照搬。

## 3. 动效与装饰

动效只服务注意力、状态反馈和空间关系。默认安静，不强制每个区块滚动淡入，也不强制逐字 tagline reveal。

一页可以保留少量品牌记忆点，但不要求凑够数量。使用前先确认：

- 是否强化主信息或关键操作？
- 是否影响阅读、性能或无障碍？
- 是否可以降级？
- 是否与相邻区块争抢注意力？

动画优先只改变 transform 和 opacity，并尊重 `prefers-reduced-motion`。

## 4. 图片与授权

需要装饰性图片时，优先选择可免费商用的图库，推荐 Pexels。记录素材来源并核对具体图片当次授权，确认允许当前使用方式；图片必须压缩、懒加载并提供合适 alt。

用户已购买 ReactBits Pro、付费图库或其他素材授权时，可以在授权覆盖当前用途的前提下直接使用，不强制替换为免费资源。未确认购买或许可范围时，不假定可用。

图库图片只用于调节阅读节奏，装饰素材不得冒充真实产品证据。真实产品截图和真实场景证据仍应优先于通用素材。

## 5. 首屏与资源性能

视觉和炫技不能以首屏不可用为代价：

- 优先加载主文案、主 CTA 和首屏关键视觉，次要演示、轮播与第三方脚本延迟加载。
- 不让统计、聊天、广告或其他第三方脚本阻塞首屏渲染和交互。
- 字体只加载实际需要的字符集、字重和样式；关键字体按需预加载，并设置合适的 `font-display`，不要预加载全部字体。
- 首屏图片提供明确尺寸，避免布局偏移；非首屏图片懒加载。
- 复杂动画、Three.js、GSAP 场景和大型组件按路由或视口拆包、延迟加载。
- 遵守项目已有性能预算；没有预算时，至少检查 Core Web Vitals、首屏请求和移动端交互响应。
