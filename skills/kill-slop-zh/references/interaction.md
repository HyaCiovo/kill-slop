# 交互、移动端与交付

## 1. 内容分层与移动端

移动端重新设计阅读和任务流程，不是把桌面三栏直接堆叠。

- 主信息、关键证据、主操作和当前状态默认可见。
- 同类功能使用 tabs、swiper 或单卡展示，避免全部平铺。
- 当前控件与对应内容尽量同屏可见。
- 长流程只突出当前阶段，完整细节可进入二级视图。
- 数据表保留关键列，次要细节进入展开行或详情视图；不自动把所有表格转成通用卡片。
- 横向标签支持自由手动滚动；选中项可以自动进入视口，但不能阻止用户回滚。
- 不通过缩小到难读的字号来硬塞内容。
- 默认不添加说明性长文案。确有必要时，将辅助说明放在语义明确的问号 SVG 图标 Tooltip 中，并支持键盘焦点和触摸操作。
- 不用 tooltip 隐藏关键信息，也不把简单内容滥用 modal 藏起来。
- 不给静态或演示内容添加没有真实刷新功能的刷新按钮。只有数据确实可刷新且操作有明确用户价值时才保留。

自动轮播不是默认答案。使用时必须：

- 提供手动控制和明确当前位置。
- 用户交互后暂停。
- 离开视口后停止。
- 支持减少动态效果设置。
- 不与视差、光标跟随等效果争抢注意力。

## 2. 主操作与交互状态

- 营销页首屏只有一个主 CTA；确有必要时最多保留一个次 CTA。产品界面则突出当前主要任务操作。
- 营销主 CTA 在首屏和页尾保持一致。弹窗标题与点击前的操作预期一致。
- 根据业务提供真实的风险降低信息，例如试用、分阶段验证或无需先迁移全部数据。
- 无死链接、空按钮、无效表单，以及与当前对象或状态不匹配的操作。
- 按需提供 hover、active、focus、disabled、loading、empty、success 和 error 状态。
- 空状态说明区域用途并提供有用的下一步；错误说明失败原因和恢复方法。
- 表单使用常驻标签，提供具体校验错误，减少不必要必填项。
- 支持键盘操作和清晰焦点，移动菜单、对话框、tabs 和 accordion 状态明确。

## 3. 语义与可访问性

- 使用合理的 `header`、`nav`、`main`、`section`、`aside`、`footer` 等 landmark。
- 保持语义化标题层级，不用字号代替标题结构。
- 文本和控件满足可读性与对比度要求。
- 图片提供符合其信息作用的 alt，纯装饰图片使用空 alt。
- 标签、tabs、accordion、modal 和轮播具备正确的名称、状态与键盘行为。
- 尊重 `prefers-reduced-motion`，不让自动播放妨碍阅读或任务完成。

## 4. SEO 与交付

- 公开页面具备 title、description、分享图、法律链接和品牌 favicon。不对私有产品界面强行添加营销元数据。
- 页面可索引时，标题和描述应与搜索意图一致；广告、私有或限时页面按需设置 noindex。
- FAQ 只有在内容真实且符合搜索需求时才考虑结构化数据，不自动添加。
- 检查站内链接、语言切换、404、法律页面和从二级视图返回的路径。
- 验证表单校验、提交、成功、失败、加载和恢复状态，而不只检查静态界面。
