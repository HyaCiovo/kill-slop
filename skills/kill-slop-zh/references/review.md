# 输出与验收

## 1. 审查输出

按优先级输出：

1. 阻断问题：用途或主任务不清、证据或数据失真、操作无效、移动端无法操作等。
2. 高优先级问题：内容重复、阅读过长、任务或转化路径不清、状态缺失等。
3. **证据或数据缺口**：缺少证据的承诺、缺少真实或明确标注示例数据的界面、建议补充的材料和验证口径。
4. 视觉与动效建议。
5. 值得保留的优点。
6. 实际验证结果与未验证范围。

建议指向具体区域或文件，并说明修改理由。不使用“命中几项就重做”的机械评分。

## 2. 新建或改造输出

按需输出：

1. 界面类型、受众、场景和主要用户任务或转化动作。
2. 主信息、界面文案和主操作。
3. 结构及每个区域的独立任务。
4. 证据、真实数据、界面状态与缺口。
5. 信息分层和移动端策略。
6. 动效、装饰图的取舍理由。
7. 适用时的 SEO、交互、性能和交付要求。
8. 实际验收结果。

只输出当前任务需要的内容，不为格式完整硬凑策略文档。

## 3. 自检清单

以下清单供 agent 在交付前自检，不是展示给用户的评分卡，也不用于机械决定重做。

### 信息、证据与状态

- 用户能否快速理解界面、受众和使用场景？
- 主要用户任务或营销 CTA 是否明确？
- 每项重要承诺附近是否有对应证据？
- 产品界面是否呈现当前状态、真实或明确标注的示例数据及恢复路径？
- 是否已单独列出证据、数据和状态缺口？
- 数字、案例、第三方背书、演示和真实结果是否清楚区分？
- 是否存在重复、空泛或没有独立任务的区域？

### 视觉与内容

- 字体、字号、间距、圆角和色板是否统一？
- 是否每个区域都套用同一种卡片或统计模板？
- 是否有装饰或动效抢占主要任务或信息的注意力？
- 是否仍存在 emoji、文字字符冒充图标、无必要控件、重复辅助说明或反复演示免责声明？
- 标题和正文是否自然换行、易于扫读？

### 移动端与交互

- 是否只是把桌面内容依次堆叠？
- 是否出现遮挡、溢出、异常断行或阅读过长？
- tabs、swiper、表格和横向标签是否支持手动操作与有用的详情访问？
- 控件与对应内容是否尽量同屏？
- 键盘、焦点态、语义化标题、landmark 和减少动态效果模式是否可用？

### 性能与交付

- 主内容、主操作、当前状态和关键视觉是否优先可用？
- 是否存在阻塞初始界面的第三方脚本、字体或大型动效依赖？
- 表单、导航、对话框、tabs、轮播和主操作是否真实可用？
- 公开页面的图片、分享信息、法律链接和 SEO 是否完整？
- 是否运行了项目相关构建、类型检查和质量检查？
- 是否检查了真实桌面和移动端界面，而不只检查代码？

构建通过只能证明工程行为正确，不能证明文案或设计更好。最终仍需验证用户的真实任务或转化路径。
