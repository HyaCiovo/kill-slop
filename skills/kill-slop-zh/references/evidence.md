# 证据与可信度

## 1. 证据优先级

1. 真实产品截图、可运行演示、真实场景图。
2. 可验证客户案例和具体结果。
3. 可验证的第三方背书，例如独立评测、有明确身份的用户证言和可查媒体报道。
4. 有测试口径的数据、检测报告和资质。
5. 明确标注的示例数据或演示流程。

第三方背书必须能追溯到人物、机构或原始内容。不要用无法验证的 logo、头像、媒体名称或引语代替证明。

证据尽量靠近对应承诺，不集中埋到页尾。

真实截图负责建立信任，装饰图只负责节奏和情绪，二者不能互相替代。没有证据时缩小承诺或提出补证据计划，不编造证明。

需要避免与真实业务系统或客户数据混淆时，只使用一次轻量来源标识，例如“示例数据”或“演示”。不要在每个区块、卡片或步骤里反复添加 mock、模拟、免责声明等文案，也不要用警告打断已经明确的演示体验。

产品界面不需要社会证明。应使用有助于用户完成任务的真实运行数据、可见系统状态、日志和产品截图。没有真实数据时，清晰地做一次示例标识即可。不得为了让仪表盘看起来完整而虚构图表数值、健康指标、活动记录或系统状态。

## 2. 证据缺口

审查时单独列出证据缺口，不只写“缺乏社会证明”。每项包含：

- 对应承诺或功能。
- 当前已有内容。
- 缺少的证明。
- 推荐补充的素材或验证口径。
- 在证据补齐前，页面应如何限制表达。

不得自行把具体数字改成含糊形容词。用户提供的数字和归因需要保持准确；缺少来源时标记并询问。

## 3. 素材真实性

- 产品截图应来自真实版本，并标明必要的时间或环境。
- 演示数据在可能混淆时做一次清晰来源标识即可，不反复添加免责声明，也不冒充真实业务结果。
- 用户评价需要有可确认的身份和授权。
- 数据需要说明对象、时间、环境和测试方法。
- 第三方报道应能访问原始来源，不断章取义。
- 装饰性图库不得用于暗示客户关系、产品界面或实际使用场景。
