# Slop 模式与修复方法

用这份目录识别常见的机器默认决策，并选择具体修复方法。它们只是语境中的候选问题，不是 lint 规则。有意的品牌选择、有意义的状态、真实顺序或用户明确要求的效果都可以合理存在。

发现记录为“模式 ID + 文件位置 + 实际问题 + 修复建议”。不要仅凭模式命中批量修改。

## 1. 颜色与表面

| ID | 模式 | 修复方法 |
|---|---|---|
| C01 | 按钮、Hero 和卡片使用默认蓝紫渐变 | 使用一个有依据的品牌强调色和平坦表面。除非光晕明确指向某个元素，否则移除彩色发光阴影。 |
| C02 | 渐变标题，或一段文字里多个染色、加粗关键词 | 使用纯色文字，通过字号、字重、位置和句子结构表达重点。最多保留一个真正有意义的强调。 |
| C03 | 用氛围渐变、卡片彩色洗底和彩色光晕制造“高级感” | 保持统一的平坦背景。用细线或克制的中性阴影区分表面，不用装饰性色块洗底。 |
| C04 | 默认语义彩虹色，或状态框的边框、文字、背景全是同一色相 | 先用文字和字重承载状态。使用中性表面，并从项目色板中选择一个有意的语义强调色。 |

## 2. 字体与强调

| ID | 模式 | 修复方法 |
|---|---|---|
| T01 | 给标题单个词使用衬线斜体，或用删除线、下划线、高亮做装饰 | 用字重、位置或有意义的换行强调。删除线只用于真实修改，下划线用于链接，高亮用于真实注释。 |
| T02 | 每个标题上方都有重复标题含义的全大写、宽字距小标签 | 删除重复标签。只有能提供类别、日期、状态或真实顺序时才保留。 |
| T03 | 把完整营销句子放到超大字号，换成三四行并占满首屏 | 把核心观点压缩成短标题，机制和细节放入正常字号说明，并检查真实宽度下的断行。 |
| T04 | 字号层级过平，或不考虑任务就给产品套终端、杂志式字体风格 | 建立少量但有明显差异的字号层级。扫描型界面使用易读无衬线和表格数字，编辑内容才用文本衬线，等宽字体用于代码。 |

## 3. 文案与证据

| ID | 模式 | 修复方法 |
|---|---|---|
| W01 | “不只是 X，而是 Y”、口号碎片、术语、戏剧性三段式和空泛转变承诺 | 直接说明谁在什么场景下，用什么机制完成什么结果。删除不增加信息的框架。 |
| W02 | 虚构统计行、假 logo 墙、匿名评价、假仪表盘，或把示例数据当真实结果 | 删除无依据证明，改用真实产品界面、可追溯案例或有口径数字。可能混淆时只做一次演示标识，不反复添加 mock 免责声明。 |

## 4. 组件与容器

| ID | 模式 | 修复方法 |
|---|---|---|
| U01 | 到处使用 emoji、用文字字符冒充图标、粗糙占位 SVG，或每个功能都配图标底座 | 使用项目图标库或有明确设计的语义化 SVG。删除无意义图标，不用 emoji 或文字字符做界面装饰。 |
| U02 | 发光脉冲状态点、装饰性 New/Popular/Beta 胶囊，以及用粗描边制造重要性 | 真实状态只保留小色点和文字。徽章只用于真实状态或版本，删除装饰性强调。 |
| U03 | 最大圆角玻璃面板、过大弥散阴影、彩色发光，或边框与重阴影重复承担分隔 | 使用统一圆角层级和实体表面。根据层级选择细线或克制的中性阴影，不无理由叠加。 |
| U04 | 内外圆角不协调，或圆角和描边位于不同元素导致边角断裂 | 内圆角按外圆角减去间距计算，或内部保持直角。边框和圆角放在同一元素上，真正分隔线保持直线。 |
| U05 | 卡片套卡片、重复彩色左边框提示，以及全大写标签组成的等权卡片网格 | 每个区域只保留一个表面。用间距、对齐和细线分组，提示只用于真正补充信息，重要内容完整展示。 |
| U06 | 在区块、导航项、清单、功能列表等无顺序内容上使用 01/02/03 装饰序号，或用编号索引复刻导航 | 只为真实面向用户的顺序编号（步骤、排名、版本）。删除区块序号、导航序号和装饰性索引数字，即便它看起来像目录；清单、权益、功能列表中的同类序号一并去掉。 |
| U07 | 装饰性小 eyebrow：每个标题上方都放极小的字距标签、把区块名重复成小 kicker、为了质感加状态行或英文副标签 | 删除只重复标题或导航的标签。只有承载真实分类、日期、状态或顺序时才保留 kicker，区块直接由标题命名。每个区域最多一个信息性 eyebrow，卡片内部的微型标签同理。 |
| U08 | 黑线铺满版式：每个区块、每一行、每个列表项、每个字段、每个导航项都加发丝线，用边框代替间距 | 删除纯装饰的线。每组最多保留一条线（表头、文档边缘、固定栏），分组改用邻近、对齐和留白。不要在同一内容上叠加区块线、行线和卡片边框。 |
| U09 | 没有视觉节奏的间距：随意外边距、相关与不相关内容使用相同间距、中文行高被压扁、区块漂浮在过大的空白带中 | 使用统一间距层级并按关系分配：相关项收紧、组间拉开。行高匹配文字（中文正文约 1.7–1.9，大标题约 1.1–1.25），在真实宽度与手机上检查，并删除不承担分隔作用的空白带。 |
| U10 | 用扩散阴影制造虚假层级：小卡片或图标使用大范围、低透明度、几乎无偏移的模糊阴影，或使用彩色阴影和发光 | 默认删除阴影，改用间距或细线。确需表达悬浮层级时，使用短模糊、小偏移、低透明度的中性阴影。不让重阴影与边框重复竞争，并检查实际渲染效果。 |

## 5. 动效

| ID | 模式 | 修复方法 |
|---|---|---|
| M01 | 所有悬停都缩放、弹跳、上浮，并默认使用 `transition-all` | 只动画传达状态的属性。优先轻微表面或颜色反馈，弹簧效果只用于真实空间位移。 |
| M02 | 加载图标偏心摆动，自动轮播与视差、光标效果叠加，所有区域都滚动入场 | 居中加载图形并围绕固定中心旋转。移除互相竞争的效果，交互后和视口外停止自动播放，支持减少动态效果。 |

## 6. 布局与交互

| ID | 模式 | 修复方法 |
|---|---|---|
| L01 | 桌面网格直接堆到移动端、控件与对应内容分离，或所有功能展开成长列表 | 重组移动端阅读和任务流程。使用 tabs 或单一活动视图，保留手动滚动，并让控件与对应内容尽量同屏。 |
| L02 | 无意义刷新按钮、说明性长文、每个区块都加 helper，或反复提示 mock、模拟 | 删除没有真实功能的控件。非必要辅助信息放入可访问的问号 SVG Tooltip，关键信息保持可见，演示来源最多标识一次。 |

## 修复顺序

1. 确认主要用户任务和品牌方向。
2. 修改共享 token 和主题决策。
3. 修改基础组件和共享内容来源。
4. 处理局部布局、样式和文案。
5. 重新定向搜索，并检查真实桌面与移动端行为。

模式命中数量下降不代表界面更好。最终验证理解、任务完成、可访问性、性能和事实准确性。
