# Kill Slop

## 适用范围

适用于落地页、官网首页、产品与价格页、仪表盘、表单、设置页、文档、设计系统组件和 Web 原型，也适用于 HTML/CSS、React、Vue、Svelte、Astro、其他 Web 框架及界面文案。

并非每个界面都有转化 CTA。产品界面有主要用户任务、当前状态和下一步操作；文档有读者问题和需要提供的有用答案。

## 核心目标

每个界面都应快速回答：

1. 这是什么，给谁用？
2. 它处理什么任务或问题？
3. 用户接下来应该注意什么或做什么？

营销页面还必须建立可信度，说明开始成本和限制。产品界面还必须呈现当前状态、数据质量、恢复路径和操作约束。

AI 味不是渐变、圆角、插画或动画本身，而是装饰先于信息、模板先于场景、口号先于证据、功能数量先于用户决策，以及桌面内容不做取舍地堆到移动端。

目标不是把界面变得冷淡或朴素，而是让每个内容、素材和交互都有明确任务。

## 第一步判断

审查、改造或新建之前，先确认**界面类型和主要用户任务或转化动作**，再决定内容、视觉和交互取舍。

- **落地页**：一个受众、一个核心报价、一个主转化动作。
- **官网首页**：允许多个受众和二级入口，但只能有一个明确的主 CTA。
- **产品界面**：确认用户的主要任务、当前状态和下一步操作，不硬套营销 CTA。
- **文档或内容页**：确认读者问题，以及页面必须提供的答案或操作路径。

如果这些判断会明显影响后续方向且无法从项目确认，向用户提问，并给出自己的推荐方案。

## 工作方式

### 主动判断，明确取舍

能够根据界面、项目规范、源码和实际效果确认的问题，直接处理：删除重复文案，重写空泛标题，合并区域，调整顺序，重构移动端分层，修复异常换行、遮挡和溢出，减少无意义动效与装饰。

原样保留不是目标。结构不合理时可以重排，内容重复时可以删除，视觉语言不匹配时可以重新设计，不局限于逐句修补。

如无必要，勿增实体。简单方案已经有效时，不新增控件、状态、抽象、依赖或说明文案。

### 拿不准方向时，带着建议提问

当不同选择会明显改变定位、受众、品牌风格、用户任务或转化路径时，一次提出相关的一组问题，并包含：

- 当前观察到的具体问题。
- 推荐方案及理由。
- 可选方向和主要代价。
- 回答将影响什么。

如果只涉及字号、间距、局部排版等可逆细节，不打扰用户，按项目规范和设计原则直接决定。

## 不可擅自更改的内容

用户提供的法律条款、合规表述、技术限制、安全边界、服务范围和合同承诺，不得擅自删改、弱化或扩大。发现疑似矛盾或表达问题时，指出具体位置并询问。

数字、日期、名称、单位、引用和归因必须保持准确。不得编造客户、功能、资质、案例、评价、指标或效果数据。

保护事实不等于保护原句。普通界面和营销文案可以重写、合并或删除；涉及上述受保护内容时，先确认再改。

缺少证据或真实数据时明确标记缺口并提出建议。不要自行把具体数字改成含糊形容词，也不要用示例冒充真实结果。

## 规则优先级

用户明确要求 > 项目现有规范与品牌系统 > 可访问性和事实准确性 > 本 skill 默认建议。

本 skill 中的组件、依赖、扫描器和视觉建议都不是强制安装或统一风格。先复用项目已有能力，再按实际需求选择。
